Lesson 200.2 · Basic Searching

Find the cause before the morning launch.

You are a junior Splunk analyst supporting Harborlight Digital Media, a company preparing to launch a major live-streamed event. During the final readiness check, employees begin reporting failed sign-ins to the production control portal. The operations team has already collected authentication and web-service data in Splunk, but no one yet knows whether the failures are isolated user mistakes, a service problem, or a broader pattern. Your assignment is to turn the available machine data into a defensible investigation before the broadcast begins.

Your mission

Start with a noisy pool of operational data and progressively narrow it into evidence the launch team can act on. Your search choices, time decisions, and interpretation of results will shape what the team knows next.

Do not choose a feed because a label sounds technical. Compare the event contents with the investigation question. Ask: which events actually record the behavior I am trying to investigate?

Step 2 · Interpret the metadata without being told the roles

The selected feed has been onboarded with the following intake profile. Your job is to infer what each metadata value is doing.

INTAKE PROFILE · PORTAL AUTHENTICATION
Destination: prod_portal
Data format: syslog
Origin: auth-gw-02
Example event: Sep 18 09:43:47 auth-gw-02 portal-auth: user=producer action=failure

A colleague proposes three interpretations. Which interpretation best matches Splunk's metadata model?

Index is the repository where ingested events are stored. Sourcetype identifies the source data's format/type so Splunk can interpret it. Host identifies the host associated with the event. Use those meanings to interpret the profile—do not rely on the names alone.

Step 3 · Diagnose a search that looks plausible

An analyst wants authentication events from the production portal and submits:

sourcetype=prod_portal index=syslog

The syntax looks reasonable at a glance. The search returns no useful authentication evidence. Based on the intake profile—not a memorized slogan—identify the configuration error.

Carry-forward mental model
You were not asked to match two obvious labels. You first selected evidence based on its contents, then interpreted an intake profile, then used that interpretation to diagnose a realistic search mistake. That is the reasoning you will use in the Search Builder next.

Refine Evidence: follow the clue without narrowing too far

Incident update
The portal slowdown is still unresolved. Your current search returns 237 events from authentication and web-service activity between 13:15 and 13:50. Operations asks: “Are the 503 responses concentrated on the same systems reporting failed sign-ins, or are we looking at two separate problems?”

Your job is not simply to make the result count smaller. You need to refine the evidence without accidentally removing context you may still need.

Live evidence sample

13:31:08 host=auth-gw-02 workstation=CTRL-18 user=msantos action=failure status=401
13:32:14 host=portal-api-01 workstation=CTRL-18 endpoint=/session status=503
13:32:51 host=portal-api-02 workstation=OFFICE-04 endpoint=/health status=200
13:33:07 host=auth-gw-02 workstation=CTRL-31 user=jlee action=failure status=401
13:33:39 host=portal-api-01 workstation=CTRL-31 endpoint=/session status=503

Notice that several fields could be useful. The challenge is deciding what interaction answers your next question.

Drill-down behavior lab

Think of drill-down as choosing what you want Splunk to do with a clue you can already see.

Expand an event
Use when you need to inspect that event's full fields and raw details. It gives you more detail about one event; it does not automatically narrow the entire search.
Select a timestamp
Use when the important clue is when something happened and you want to investigate nearby activity around that point in time.
Select a field name
Use when you want to understand the field itself—its values, frequency, or field-related search/report options—before deciding which value matters.
Select a field value
Use when a specific value such as status=503 has become your hypothesis and you want to add or remove that value as a search filter.

Memory cue: Event = inspect it · Time = investigate around it · Field name = understand the field · Field value = filter by the value.

Search mode decision lab

Search mode changes how much search detail Splunk returns while processing your search. It does not replace good search terms.

Fast
Prioritize speed when you already know what you are looking for and do not need the richest field discovery/detail.
Smart — default
Let Splunk balance speed and detail based on the search. This is the normal starting point when you do not have a special reason to force another mode.
Verbose
Favor fuller event/field detail when deeper investigation matters more than speed.

Important: Search mode answers “How much detail should Splunk return?” Drill-down answers “What should I do with this clue?” They solve different problems.

Refinement is a sequence of questions, not a race to the smallest result count. First understand the clue, then decide whether to filter by it, and choose a search mode that fits the depth of investigation you need.

A useful self-check is: Am I trying to inspect one event, investigate a time, understand a field, filter by a value, or change how much detail Splunk returns?

Challenge 3 · Decide whether snapping changes the evidence window

At 15:45, an analyst proposes earliest=-h@h latest=now. Before using it, determine the actual start time produced by the snap-to-time operator @h.

Hint available only if needed: @h means align to an hour boundary; it is not simply another way to write “60 minutes ago.”

Analyst Checkpoint

Mental model

earliest= answers “When should Splunk start looking?” latest= answers “When should Splunk stop looking?” The Time Range Picker is useful for interactive searching, but time modifiers written into the search can explicitly define the window. The @ operator snaps a relative time to a boundary such as the start of an hour.
