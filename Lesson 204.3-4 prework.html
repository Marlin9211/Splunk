05 · Reporter // Triage Recall Strip

Incident Intake Timeline: Reconstruct the Analyst Handoff

Asterion Civic Systems received a suspicious authentication alert involving a privileged account. The overnight analyst left five incomplete investigation checkpoints. Reconstruct the source-defined alert-triage workflow so the incoming analyst can understand what must be established before the case moves forward.

Your task: Work through the five checkpoints in order. At each checkpoint, read the evidence already available and choose the investigation question that belongs at that point in the workflow. The choices are intentionally similar because a real investigation may eventually ask all of them. Focus on what the analyst needs to establish next. Select Review investigation sequence when all five checkpoints are filled.
Reporter boundary: This activity asks you to recall and recognize the five source-defined alert-triage questions and their sequence. You are not diagnosing the incident or selecting remediation actions.
CHECKPOINT 01 · VALIDATION

The alert has fired, but its meaning is not yet established.

The SOC has a privileged-authentication alert and basic event details. Before treating the event as a confirmed security incident, the analyst needs to establish the first decision point in the triage workflow.

CHECKPOINT 02 · EFFECT

The event has now been validated as an incident.

The analyst has enough evidence to confirm that the activity was not simply benign account behavior. The next checkpoint determines whether the confirmed activity achieved an effect.

CHECKPOINT 03 · RECONSTRUCTION

The incident is confirmed and its immediate effect has been considered.

The handoff still lacks a clear account of the activity itself. The incoming analyst needs the checkpoint that establishes the sequence and nature of what occurred.

CHECKPOINT 04 · SCOPE

The analyst now understands what happened on the initially identified system.

The investigation cannot assume the activity remained isolated. The next checkpoint establishes whether the incident extends beyond the first observed asset.

CHECKPOINT 05 · RESPONSE

Validation, effect, reconstruction, and scope are now documented.

The investigation record contains the information needed to reach the final question in the source-defined triage workflow.

11 · Translator // Content Narrowing Route

SSE Content Request Workbench: Build the Narrowing Route

Asterion's SOC receives content requests from analysts who know what they need to find but do not always know which SSE filter expresses that need. You are supporting the content desk. For each request, interpret the analyst's intent and select the filter that most precisely narrows the library in the requested way.

Your task: Review five realistic analyst requests. Each request contains three plausible SSE filters. Choose the filter that answers the analyst's specific information need—not simply a filter that could also produce useful results. The options are intentionally concise and similar in length, and the correct position changes from case to case. Incorrect selections must be revised. After a correct decision, the expert review explains why every option is right or wrong for that request.
Translator lens: Focus on what each filter means: Keyword = terms, Journey = Security Data Journey stage, Category = security concern, Data Source = supporting data/technology, and Featured = highly recommended by Splunk Security SMEs. Filtering narrows content; it does not by itself prove local deployment readiness.
Request 01 · Topic Search“Start with the phrase local admin.”

The analyst is not yet asking about maturity, telemetry, or recommendation status. The immediate goal is to reduce the library using a specific term associated with the behavior being researched.

Request 02 · Maturity Alignment“Show content appropriate to our current maturity stage.”

The analyst wants to narrow the library according to where the Splunk deployment sits in the Security Data Journey rather than by the source providing the data.

Request 03 · Security Concern“Keep the search centered on this type of security problem.”

The analyst wants an organized security-content grouping rather than a literal search term or a filter based on the telemetry supporting the detection.

Request 04 · Telemetry Fit“Which content is powered by the data sources we are considering?”

The analyst wants to narrow results according to the technologies and data sources behind the use cases, not according to maturity stage or SME recommendation.

Request 05 · SME Recommendation“Surface content Splunk Security experts highly recommend.”

The analyst wants recommendation status to narrow the library rather than using a topic term or an organized security concern.
